# Миграция

Остальные страницы описывают svir **0.2** как он есть. Эта перечисляет, что
меняется при обновлении, начиная с новейшего релиза. Релиза, который ничего от
вас не требует, здесь нет; все изменения, включая добавления, — в
[журнале изменений](https://github.com/RomanEmreis/svir/blob/main/CHANGELOG.md).

Изменения каждого релиза делятся на два вида:

- **Не компилируется**: компилятор или Cargo находят каждое место. Исправление
  названо.
- **Компилируется, но отвечает иначе**: на это ничто не укажет, поэтому запись
  говорит, что искать.

## 0.2.0

### Не компилируется {/* #does-not-compile */}

- **Фича `tls` теперь называется `tls-ring`.** Cargo останавливается на
  манифесте, где указана `tls`. Переименуйте её:

  ```toml title="Cargo.toml"
  [dependencies]
  svir = { version = "0.2", features = ["tls-ring"] }
  ```

### Компилируется, но отвечает иначе {/* #compiles-answers-differently */}

- **В фичах по умолчанию нет TLS.** Сборка с фичами по умолчанию, которая
  обращается к URL `https://`, получает `ErrorKind::Config` из `build()`, и
  ошибка называет `tls-ring` и `tls-aws-lc`. Ищите зависимость svir без ключа
  `features` в крейте, чей клиент обращается к хостинговому серверу, и
  добавьте `features = ["tls-ring"]`. Сборка с
  `default-features = false, features = ["client", "tls-aws-lc"]` работает как
  работала, и её можно сократить до `features = ["tls-aws-lc"]`. См.
  [Фичи и TLS](../client/features).
- **Изображение при допуске по контексту считается не больше чем за 16384
  токена.** Раньше оно считалось по длине base64. С заданным `context_tokens`
  запросы с большими изображениями, которые отклонялись, теперь допускаются.
  Для модели, которая берёт за изображение меньше, задайте `image_tokens`; см.
  [допуск по контексту](../basics/attachments#context-admission).
- **HTTP 529 — это `ErrorKind::Transport`**, его можно повторить. Раньше это
  был `Unsupported`. Код, считавший 529 окончательным, теперь его повторяет, и
  `Retry::transient` тоже.
- **`400` со словами о слишком длинном промпте — это `ContextOverflow`.**
  Раньше это был `Unsupported`.
- **`ClientBuilder::header` не принимает `anthropic-version`**: svir пишет его
  для Messages API. Клиент, который его задавал, получает `Config` из `build()`.
- **Сохранённые данные читаются как раньше.** `Reasoning::signature` и
  `Completion::parts` новые, и в том, что сохранил 0.1, их нет; они читаются
  пустыми. `match` по `ReasoningSource` принимает новые `Thinking` и
  `RedactedThinking` в ветке с подстановочным шаблоном.

## 0.1.7

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-1 */}

- **При завершении `Length` список `calls` пуст.** Вызовы, которые оборвал
  лимит вывода, лежат в `cut_calls` как `ToolCallDelta` и не для выполнения.
  Код, который выполняет `calls`, не проверив причину завершения, выполнял
  вызовы, которые могли быть обрезаны; теперь для такого ответа он не
  выполняет ничего. Ищите `done.calls`, прочитанный раньше `done.finish`.
- **Обрезанный вызов без ID или без имени сохраняется.** При завершении
  `Length` это был `ErrorKind::Protocol`, и ответ терялся вместе с ним; теперь
  ответ завершается, а вызов лежит в `cut_calls`.
- **Нужны как минимум `rustls` 0.23.46 и `tokio` 1.53.3.** Lock-файл,
  зафиксированный ниже, получит их при `cargo update`.

## 0.1.6

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-2 */}

- **Вызов именованного инструмента, который сервер завершает с `stop`,
  завершается с `ToolCalls`**, как его присылает vLLM. Раньше он падал с
  `Protocol`.
- **Рассуждения, присланные и под `reasoning_content`, и под `reasoning`, —
  одна запись** из `ReasoningSource::ReasoningContent`, как их присылает
  mlx-vlm. Раньше их было две, и они показывались дважды.
- **Сообщение сервера читается из `detail`**, когда в теле его ошибки нет
  `error`, а переполнение контекста, о котором там сказано, в том числе
  словами вроде «context budget», — это `ContextOverflow`. Оба случая были
  `Unsupported` без сообщения.

## 0.1.5

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-3 */}

- **Отказ читается.** Строгий режим отклонял его с `Unsupported`, а мягкий
  завершался с `Stop` без текста. Теперь отказ — это текст, а причина
  завершения — `FinishReason::Refusal`, которую написанный раньше `match`
  принимает в ветке с подстановочным шаблоном.

## 0.1.4

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-4 */}

- **Неудачный вызов из `Tools` помечается `is_error`**, и его `content` больше
  не начинается с `error: `. То, что читает модель Chat Completions, не
  изменилось. Код, искавший префикс, читает `is_error`.
- **Текстовый файл проверяется на UTF-8 во время отправки тела**, а не только
  при измерении: файл, изменившийся в промежутке, падает с `Attachment`.

## 0.1.3

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-5 */}

- **Промпт, заблокированный контент-фильтром, — это
  `ErrorKind::ContentFilter`**, и отправляется он один раз. Раньше это был
  `Unsupported` после второй попытки, оплаченной ещё раз.
- **Асинхронный контент-фильтр Azure читается.** Его аннотации были
  `Unsupported` в строгом режиме; теперь блокировка делает причину завершения
  `ContentFilter`, даже после того как весь ответ уже пришёл.

## 0.1.2

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-6 */}

- **Отфильтрованный ответ завершается с `FinishReason::ContentFilter`.**
  Раньше это был `Unsupported`.
- **Мягкий режим падает на незнакомой причине завершения и на содержимом после
  причины завершения**, как и строгий.

## 0.1.1

### Компилируется, но отвечает иначе {/* #compiles-answers-differently-7 */}

- **Лимит `wire_bytes` по умолчанию — 64 МиБ.** Раньше было 4 МиБ, и длинные
  ответы обрывались с `ResponseLimit`.
- **Встроенные теги `<think>`, разбитые между дельтами, отделяются.** Дельта,
  в которой была только часть тега, оставляла тег в тексте ответа.
